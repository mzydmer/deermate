# ADR 0013 · 有记忆的私人首页：复用语义记忆，Go 提供关注与简报产品层

- Date: 2026-10-29
- Status: **Proposed，随 M4.4 spec 待评审；未实施。**
- Spec: [有记忆的私人秘书与今日简报](../specs/m4-personal-memory-briefing.md)
- Technical design: [本地 DeerMem 原型、关键时序与状态](../specs/m4-memory-technical-design.md)（2026-10-30 补充，仍为 Proposed）

## 背景

用户希望私人秘书根据长期记忆与新进展，在首页给出个性化简报，并能一键跟进历史对话或开启感兴趣的新话题。当前首页已有真实任务和对话入口，最小部署的记忆仍禁用。项目要求 Go 负责主/管理/用户及公开 API，同时优先复用固定 DeerFlow 的内部能力。

## 拟议选择

复用本地 DeerFlow 记忆 provider 作为语义事实的内容主源。Go 增加个人资料/策略、关注主题、来源证据索引、简报快照和动作 intent，使用既有单机存储与鉴权。该层是产品投影与执行接纳，不再实现第二套通用记忆或向量引擎。

固定版本的 DeerMem 采用 Markdown 事实文件、用户级 JSON 摘要和可重建 SQLite FTS5 索引。首期拟用其 FTS5/BM25 检索；默认上下文注入与 FTS 检索是不同路径，受限适配器需要显式组合范围过滤、检索和预算化注入。上游自动提取队列仅在进程内，Go 还需持久作业/回执；提交前策略与删除校验、项目授权过滤和摘要谱系也不是上游已有的 DeerMate 契约。未完成谱系前不直接注入旧共享摘要。

把“关注对象”“已核实事实”“生成的建议”“用户发起的动作”分开建模。记忆决定相关性，任务/外部来源的版本证据决定进展。简报整理器不能自行执行动作。首页 GET 使用快照或确定性回退，不启动 Native 任务；受限的有界后台整理与用户点击动作分别记录预算和身份。

首页动作继续走现有对话/权限链路。历史跟进保持 thread/incarnation 和 Native 关联；新话题创建新的对话、不复制原绑定。进度跟进采用服务端只读能力集合；“继续执行：具体下一步”使用原项目权限，只续接一轮原任务。两种动作分别接纳，不能仅靠提示词限制工具。用户点击前能看见实际问题和范围，点击后不增加重复确认步骤。

## 考虑过的其他方向

| 方向 | 取舍 |
| --- | --- |
| 每次打开首页都把全部历史交给模型 | 来源时间和成本难控制，容易产生过期陈述，也重复发送无关私人数据 |
| 只展示最近对话或任务列表 | 可复用，但缺少长期关注、可解释推荐和跨会话个人上下文 |
| 一开始引入新的外部记忆 SaaS/向量库 | 增加部署、费用和数据边界；当前本地 provider 与结构化关注索引需先验证 |
| 同一点击任由通用 Agent 规划并执行 | 动作范围不够明确，可能与单会话关联、权限和重试规则冲突 |

## 后果与待验证点

- 同时维护 provider 内容、Go 展示投影和删除版本，需要事件幂等、可重建索引及失效协议。
- 先验证 provider 的本人隔离、事实更新/删除、检索和注入契约；不支持的能力不能静默切换为全局操作。
- 显式用户更正/遗忘优先；待写入任务和缓存需检查当前版本，防止内容复活。
- 外部来源的接入和同步是单独范围，首页不能从历史记忆推断当前外部进展。
- 当前 2 GiB 单机的内存、队列公平性和模型成本需要实机验收；本 ADR 不声称性能、云模型隐私或第三方保留策略已经验证。
- 本轮仅提出设计，不启用现有记忆、回填历史、调度后台任务或部署代码。
