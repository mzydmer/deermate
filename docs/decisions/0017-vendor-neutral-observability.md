# ADR 0017：标准 OTel 核心与独立的厂商接入配置

- 状态：Accepted
- 日期：2026-11-10
- 依据：[可观测规格与计划](../specs/vendor-neutral-observability.md)

## 背景

用户要求先接入 ARMS，同时开源项目不能依赖阿里云。当前 Go、DeerFlow、受控 Relay 与本机 Worker 之间有持久业务身份，但没有标准调用链上下文。仅安装厂商探针不能保证异步队列和原生会话的完整关联。

## 决策

使用标准 OpenTelemetry API/SDK 和 OTLP/HTTP，核心实现没有云厂商 SDK、Key、账号或区域。业务跨度及上下文传播放在原有接纳和执行边界；厂商特定配置独立存放，首个运行后端为 ARMS。开发者可以关闭遥测，或把同一 OTLP 输出发送到其他兼容后端。

首个关联在独立表中持久保存；遥测不能改变任务指纹、授权和副作用重试策略。公开入口隔离外部关联上下文，内部只传播校验后的白名单。默认不导出正文和认证材料，Exporter 故障不影响业务执行。OTel 是诊断资料，不替代任务账本或独立验证。

## 替代方案与后果

直接在业务代码依赖 ARMS/AgentLoop SDK 会绑定厂商；完全依赖自动探针会留下异步/原生边界；自创 Trace 格式会增加跨语言与后端维护成本。采用标准 SDK 增加少量可选 Python 依赖及 Go 依赖，需要维护上下文、隐私与协议回归。原生 Agent 内部 Trace 能力仍需按实际版本验收；厂商界面对 Span links 的展示不能代替准确的业务映射。
