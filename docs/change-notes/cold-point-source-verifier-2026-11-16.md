# 共同停写点来源验收

涉及 `scripts/verify_single_host_restore.py` 和 `tests/test_single_host_backup.py`。第三轮实机演练在来源详情比较处严格失败；只读归档/恢复卷以及隔离恢复 API 的复核表明，恢复对象与归档完整一致，归档有一条晚于早期采样的使用记录。早期 API 对象没有持久保存，不能事后捏造其完整差异。

修正仅影响离线合成验收：通过真实 Inbox 明确采集来源，保存早期及冷点前后对象，从已验证归档的数据库及配套 WAL/SHM/journal 私有副本读取完整来源预期，保留全文、owner、Thread、message、哈希和使用记录比较。增加早期采样后新增 usage、实际未 checkpoint WAL 的回归及四类来源身份/正文反例。没有改变备份格式、恢复动作、客户交互或权限，现有产品指南/待发布日志中的冷备与隔离边界仍成立，无需新增客户能力声明。内部 runbook、专项规格和实际状态同步更新；第三轮失败及两个原卷保留。
