# 今日关注与私人秘书首页

M4.4c–e：基于本人显式关注、真实任务记录和长期目标的首页闭环。Go 提供公开 API 与动作账本；内部 Python 适配固定 DeerFlow。完整目标见[记忆规格](specs/m4-personal-memory-briefing.md)，本次范围见[实施说明](specs/m4-personal-home-implementation.md)。

## 使用步骤

1. 登录工作台，展开「管理关注」。按标题选择已有对话（没有标题时显示“未命名对话”），或粘贴本站历史对话链接，填写希望跟进的目标，再点「关注这个对话」。记录不会因对话超出最近 20 条而消失。
2. 首页「今日关注」最多展示三项，优先显示失败、待输入和未读变化。每项有原对话入口、记录时间及核对时间；已有后台任务还可打开原结果。只有任务记录确有独立验证 exit 0，才显示验证通过。
3. 展开「跟进这个话题」，预览固定问题，点「一键只读跟进」。问题发到原对话，回答完成后点「查看跟进结果」。这一次运行的模型工具集合为空，工具入口也强制拒绝执行；下一条本人普通消息仍遵守原对话的正常能力。
4. 已有关联 Codex 任务时，可展开「继续执行具体下一步」。服务先核对原项目和执行器；填写这一次具体要做的事，再点「继续执行这一项」。只续接一轮原会话，不创建第二个根会话。连接不满足、待输入、忙碌或结果未知时，需要先处理原记录。
5. 在「个人设置与记忆」开启个人记忆，保存类型为「目标」的事实，并另行开启「根据长期目标推荐新话题」。首页最多提供两个问题和推荐原因；点「开始这个话题」才创建新对话。新话题只读起步，不继承旧 Codex 绑定，采用建议不会反向采集为新的兴趣。
6. 用「标记已读」「今天先不看」「暂停」「完成关注」「不再关注」控制列表。问候、简报日期及今天的截止统一使用个人资料的 IANA 时区；未保存时按 UTC 显示，可在个人设置中选择设备时区。取消关注保留原对话；来源删除、归档、换代或范围变化后，旧卡片内容会隐藏。

普通账号可以管理本人关注；执行动作仍需要已有管理员运行权限。关闭记忆停止个人记忆的采集与注入，也隐藏目标推荐；显式关注及原任务入口仍可用。私人数据连接、外部订阅与 Claude 适配器不由这个首页自动开通。

## 证据与费用

首页 GET 和刷新只读有界的现有记录，不调用整理模型或 Native。每个用户最多 50 个未删除关注、20 个活动关注；最多三条首页进展、两条目标建议。简报版本由内容、策略、日期与可用性决定，不因每秒核对时间改变。显式刷新可持久化同版本快照；展示仍重查当前来源，不把旧快照当作权限。

“执行结束”和“独立验证通过”分开；取消请求不等于已停止；执行端同步超过五分钟或跟踪失败时标记最后已知状态。没有外部连接时不会声称 GitHub 或竞品已有新进展。点击跟进/新话题会运行所配置的聊天模型，可能产生其供应方费用；执行续接走原 Worker 权限和额度。

## 动作恢复

服务端先固定问题、来源版本、owner、目标会话及范围，持久化 intent 后才提交。相同问题与来源的重复点击返回同一记录。15 分钟未接纳的预览可在用户再次点击并重检来源后续期；已经提交或结果不明的记录不会变成新的提交。

网络中断后页面只 GET 核对原结果，自动核对有时间上限，可点「核对原结果」继续。服务重启保留 intent。原生提交丢失回执时保留 session 的待核对状态，不能通过首页换会话重发。若预览尚未被接纳，页面显示这一事实，并允许显式重试原 intent。

## 接口和部署

所有写接口复用 Go 登录、CSRF、`X-Expected-User-Id` 和本人过滤。

| 接口 | 行为 |
| --- | --- |
| `GET/POST /api/me/attention-topics` | 本人列表 / 显式关注；创建使用 `operation_id` |
| `PATCH /api/me/attention-topics/{id}` | `expected_revision` 与动作；已读另传 `evidence_revision` |
| `GET /api/me/briefing` | 当前确定性简报；不发起运行 |
| `POST /api/me/briefing/refresh` | 重核现有来源并保存版本快照 |
| `GET /api/me/attention-topics/{id}/continuation` | 只读核对原 Codex 会话，返回项目/执行器/范围指纹 |
| `POST /api/me/briefing/actions` | 准备 `followup`、`new_topic` 或 `continue` |
| `POST /api/me/briefing/actions/{id}` | 至多一次提交；后续只核对 |
| `GET /api/me/briefing/actions/{id}` | 核对原操作，不重放 |

原始插件入口和保留的 extension 幂等键不能从公开代理绕过接纳。必须同步更新 Go、Gateway wheel/配置和完整 frontend overlay；旧组件混跑不受支持。现有本地与云部署需按部署指南另行升级；本次本地合成验收不表示已部署到公网。

## 验证与边界

[`verify_personal_memory.py`](../scripts/verify_personal_memory.py)运行实际 Go/Gateway/DeerMem API，并包含首页跟进、新话题和重启后幂等核对。[`verify_personal_home.cjs`](../scripts/verify_personal_home.cjs)使用[前端验收环境变量](../frontend/README.md)，只能指向独立 loopback 合成环境；需要名为 `capture-fixture` 的离线模型、全新持久卷和合成账号。它从真实页面点击并检查原对话结果、新对话、反馈、手机/深色和错误恢复。

不把单元 Submitter 或 Fake 模型当作真实 Codex/供应方验收。语义自动提取/归并、跨主题语义合并、共享项目权限、历史导入、模型整理作业预算、外部订阅和实际 2 GiB 性能仍待实施或独立验收。完整 MEM-01–MEM-21 尚未全量通过。
