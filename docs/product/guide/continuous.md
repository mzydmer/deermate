# 持续秘书与工作

登录后在「助手」交代目标，在「我的工作」查看工作安排，无需单独启用。秘书沿用对话模型；没有选择时使用已有模型列表中的默认模型。当前仍为 Alpha，管理员可停用服务。旧版本可能仍显示启用开关，实例是否已升级见 [变更日志](/docs/changelog)。

如果提示等待模型，请从统一模型设置配置受支持的模型；原输入会保留等待处理。无需重复配置秘书模型，也不要为等待中的输入重新发送一份。

## 创建一项工作

在「助手」输入目标。秘书会答复或提出工作建议，按已注册项目和当前授权安排。在「我的工作」打开详情，核对目标和范围。

秘书入口保持自己的连续上下文，具体执行使用各工作的执行对话。工作被实际接纳前，不会提供虚构的执行对话链接。

## 执行与追问

打开工作详情，核对目标和范围后执行。系统会检查设备、授权版本、项目、协议和原会话轮次。

后续要求从该工作的详情中发送，明确写出本轮下一步。不同工作的草稿分别保留；已结束工作不再提供追问输入。其他入口已经推进原会话时，先重新核对，再明确发送下一步。

## 暂停、关闭与停止

「暂停」阻止后续派单；「关闭」结束该工作的后续处理；「请求停止」需要等待执行端确认。回执未知时点「核对原结果」，系统只查原操作。

页面读取失败会提示内容可能过时，并停用依赖这些数据的写入。可用的原操作核对仍可继续。助手首页在当前浏览器会话中保留未确认发送的原文和操作编号，刷新后仍核对同一次发送；关闭浏览器会话后先查看工作记录。各工作详情的未确认请求仍只在当前页面保留，刷新后优先核对原结果。

## 管理记忆

侧栏打开「关于你」，或打开设置中的「记忆」，查看、搜索、纠正和遗忘本人记录。新账号默认整理普通表达，已有暂停选择保留，详见 [记忆管理](/docs/guide/memory)。

## 观察 GitHub 来源

来源观察需本人明确启用，自动执行额度初始为零。旧版本暂停过的背景处理不会因登录或直接对话而恢复。首期仅支持管理员固定配置的单个 GitHub 仓库。启用来源后先建立当前基线，再添加观察规则；不会回放全部历史事件。

在观察模式下，候选由本人接受。已经绑定执行对话的更新进入原工作上下文，不自动开启新原生轮次。来源不可读或停用后，旧内容会隐藏。

## 自动处理与额度

自动执行需要本人明确选择执行模式、限定项目与授权，并设置非零额度。默认自动执行额度为零。调整额度不会恢复已经暂停的观察；需要观察时明确点击「启用来源」。首期自动原生轮次最多每日两次，秘书路由与评估合计每日最多二十个接纳请求，按 UTC 记账。

额度预留不等于供应方实际账单；结果未知的投递继续占额。规则更新不回放旧候选，来源达到容量上限时会暂停推进并显示原因。

## Alpha 限制

真实 GitHub、真实模型与真实 Codex 的完整持续闭环、完整界面状态矩阵和研究对照仍待单独验收。现有离线链路结果不能推断所有线上环境都可用，详见 [变更日志](/docs/changelog)。
