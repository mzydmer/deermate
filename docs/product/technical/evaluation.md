# 研究问题与评估方法

DeerMate 的研究目标是提供可运行的系统设计、明确不变量和可复现评估。以下为待开展的研究方案，当前没有 Router 对照或消融结果，不能据此声称效率、质量或注意力成本改善。

## 研究问题

- 持久 Router 与单协调会话相比，是否改善跨事件的工作连续性？
- 有界引用与完整上下文相比，如何影响质量、读取量和 token 成本？
- 发送屏障与原操作核对能否在故障注入下减少重复执行？
- 观察、本人接纳与有界自动处理如何影响完成率和人工介入？
- 来源失效与遗忘机制能否阻止旧内容重新进入后续上下文？

内部研究计划将实施与证据划分为五项：R-EVAL-01 合成数据集，R-EVAL-02 对照与消融，R-EVAL-03 指标，R-EVAL-04 故障注入，R-EVAL-05 重复实验与复现材料。上述问题在这些实验中分别检验，当前均未形成比较结论。

## 对照与消融

使用相同任务集、事件到达时间、模型版本、项目快照、工具范围、授权和预算，对照 A 单协调会话、B 所有事件经 Router 的 Router/Worker、C 订阅直通的 Router/Worker。A 保留等价后台工具，不人为强制同步等待。分别关闭引用召回或事件合批进行消融，每次只改变一个因素。

故障注入只在隔离的合成环境中进行，不对真实账号、设备或外部服务重放副作用。每组预先固定运行配置、随机种子、缓存条件与重复次数，建议至少五次；真实模型实验还需记录供应方和日期。

## 指标口径

| 指标 | 建议计算方式 | 解释限制 |
| --- | --- | --- |
| 完成率 | 满足事先定义的验收任务数 / 总任务数 | 人工盲评和自动测试分别报告 |
| 重复执行率 | 同一逻辑操作发生额外执行的数量 / 逻辑操作数 | 查询重试不能算成执行 |
| 恢复核对率 | 注入故障后恢复到正确原结果的操作数 / 故障操作数 | 另报未知与拒绝，不能从分母删掉失败 |
| 延迟 | 从接纳到结果的 p50、p95 和最大值 | 区分排队、执行、核对和冷启动 |
| 上下文成本 | 每项工作读取字节、对象数、模型 token 与实际费用 | 配额预留不是账单 |
| 人工介入 | 每项工作的确认、纠错和升级次数 | 次数只是注意力成本的代理指标 |
| 来源治理 | 失效来源泄漏数、迟到复活数和有效引用覆盖率 | 零泄漏需说明测试集合和覆盖范围 |

## 可复现材料

发布任务定义、可公开的合成事件、代码版本、固定依赖、环境与硬件、授权策略、故障时间点、原始脱敏记录及统计脚本。保留失败尝试，避免只展示成功样本。

离线协议实验、真实供应方实验和用户研究分别形成证据。小样本报告每次运行结果；样本足够时给出置信区间，并说明聚合单位和缺失值处理。

## 当前已有证据能说明什么

2026-11-04 的历史本地测试使用一千个合成工作、一万个事件，每个读取端点一百次、并发一。在合计 1472 MiB 容器限额下，列表、详情、引用与搜索 p95 分别为 69.666、39.341、42.354、84.995 ms。数据来自保留的本地验收记录，本次文档建设没有重跑该实验。

这只描述指定环境的有界读取。它不是冷文件系统测量、真实两 GiB 主机容量结论、模型质量评估或 Router 对照收益。早期全历史搜索未达标的失败也保留在历史记录中。
