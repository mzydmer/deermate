# 研究问题与评估方法

首批 Router 离线对照已完成 36 项计划和单独六项同版本复跑。主批次 33 项 complete、2 项 outcome_unknown、1 项 failed；复跑六项全部 complete。实验生产源码固定为 7c84904，原始 JSON/JSONL、清单、数据/配置哈希、独立判定和重算脚本已公开并列入本页来源。它们描述脚本 toy 环境，不证明真实模型质量、账单或注意力收益。

## 实验与完成标准

A 为单协调会话，具备真实异步后台 MCP 工具；B 所有事件经 Router；C 将已有权威订阅的绑定事件直接附加原工作。A/B 在真实 Router 完成后确定性附加同一权威关联，不声称模型自行判断归属。三组使用相同项目快照、六配对 seed、六种轮换顺序、事件时刻、预算和验证。真实 Go、固定 Gateway、MCP/Relay 与 Worker 运行，Provider/Native 为离线 fixture，没有付费调用或生产部署。

S1 在后台执行时投递固定事件及前台问题，并用第二个实际认证的 owner 核对越权拒绝；S2 在原 run/MCP/chat journal 持久化后真实关闭一次 coordinator ACK，恢复仅查询原身份。判定器重核实际 RPC、同一 root/turn/workspace、补丁/文件哈希、真实独立测试及 effect journal，不信任模型或 runner 的成功声明。只有公开 MCP、原 Go 操作/Inbox、相关 runs 和通知全部收敛，再经过四秒稳定尾部才算完整完成。

真实双副作用负例在同一个 root/turn 写两次相同变更，独立测试仍为 0，判定器仅因两条 effect 拒绝。错 root、缺测试、越 owner、超范围、缺证据和混用 batch 的反例也被拒绝。

## 主批次结果

主服务指标是持久接纳到实际完整 JSON 成功 flush，单位毫秒；客户端发送到完整读取另列原始汇总，两种时钟不相减。服务 flush 不是浏览器精确显示时刻。分位数用 nearest-rank ceil(q×n)；本批 n 为 5 或 6，p95 即最大值。未知与失败保留计划分母，缺失延迟不填零。

| 场景与组 | 完整完成/计划 | 延迟观测/计划 | 服务 p50 / p95=max (ms) |
| --- | --- | --- | --- |
| S1 A | 6/6 | 6/6 | 7659.9 / 8041.1 |
| S1 B | 6/6 | 6/6 | 5269.4 / 5827.4 |
| S1 C | 5/6 | 5/6 | 5476.7 / 5808.9 |
| S2 A | 5/6 | 5/6 | 7453.6 / 8042.7 |
| S2 B | 5/6 | 6/6 | 7813.7 / 8387.4 |
| S2 C | 6/6 | 6/6 | 8013.9 / 8179.7 |

三项未完整通过分别为 S1-1104-C 前台 30 秒超时、S2-1103-A 设备配对 503 未进入执行，以及 S2-1106-B 已找回原 run 但 Go 操作/Inbox 到总截止仍未收敛。前两项延迟删失。两个收敛失败保留 SQLite 锁冲突日志，具体竞争写入方未知；没有补跑失败格、重放 mutation 或延长预算。

原生根和 effect 的额外执行为 0/35 observed，另有 1 项执行未观测，不能说 36 项全部没有重复。S2 完整端到端恢复率：A 5/5 已注入观测、5/6 计划；B 5/6 观测及计划；C 6/6。query 确认同 run 单独不足以计完整恢复，B 的失败不等于重复执行。

六项复跑使用同一冻结源码、数据、配置和镜像，终态及 Worker/MCP/Go 操作/Native turn/模型调用/root/effect 的离散计数均与对应主样本一致；时间值作为新测量单列。复跑不替换主批次失败。

## 指标与结论边界

原始汇总保留逐次延迟、排队和验证耗时、B−A/C−B 配对差、角色调用及序列化输入字节。只有双方均有观测才计算延迟配对差。A 的 coordinator 调用完整计入；未完成样本的调用记录可能截断，不能把部分观测总数当成相同已完成工作的成本，也不把 UTF-8 字节换算账单。

通知统一使用 owned-admission-v1 测试输入适配，保留完整原通知及哈希，输入上限仍为 12,000 bytes；这不代表默认生产通知已在该上限内验收。小样本、toy 修复和两个固定场景不覆盖消融、其他中断点、真实质量/费用、用户介入或容量。R-EVAL-01–05 的完整研究验收仍未勾选。

## 复核与研究问题

公开材料提供逐计划 raw、JSONL、不可变清单及一个 aggregate 命令重新独立判定，保留准备失败、超时和未收敛。后续继续检验跨事件连续性、有界引用质量、原操作恢复、来源失效和可纠正记忆；新的配置和任务使用新批次，生产 SHA 与整理报告的提交分开记录。

## 当前已有证据能说明什么

2026-11-04 的历史本地测试使用一千个合成工作、一万个事件，每个读取端点一百次、并发一。在合计 1472 MiB 容器限额下，列表、详情、引用与搜索 p95 分别为 69.666、39.341、42.354、84.995 ms。数据来自保留的本地验收记录，本次文档建设没有重跑该实验。

这只描述指定环境的有界读取。它不是冷文件系统测量、真实两 GiB 主机容量结论、模型质量评估或 Router 对照收益。早期全历史搜索未达标的失败也保留在历史记录中。
