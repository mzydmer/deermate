# 记忆、上下文与来源治理

长期事实、今日关注与持续工作分别承担不同的上下文职责。当前实现以显式采集、确定性读模型和有界关键词检索为基础。

## 三类记录

| 记录 | 用途 | 当前采集方式 |
| --- | --- | --- |
| 个人事实 | 偏好、长期目标与背景 | 手动保存，或本人开启后的明确记忆指令 |
| 关注与简报 | 把原对话和任务证据带回首页 | 本人显式关注、确定性读取已有证据 |
| 持续工作与事件 | 长目标的来源、决策和执行链路 | 受限来源同步与工作操作 |

历史事实不能当作新的任务进展，简报快照不能当作当前访问权限。自动语义提取、项目级共享记忆、历史导入和跨主题归并仍需后续实现。

## 设置中的管理入口

设置 → 记忆与首页记忆管理链接使用同一个本人记忆组件及 Go 身份边界，不创建另一套共享记忆存储。管理入口可直接打开，记忆注入与明确采集的已有开关保持原选择；可见入口不意味着自动采集。

## 来源与版本

采集时记录本人身份、来源对话及其 incarnation、来源版本和个人策略版本。来源编辑、删除、换代或权限失效后，旧内容不能继续参与展示、检索和注入。

个人记忆通过窄适配器复用固定 DeerMem 的文件事务、FTS5 与上下文格式化。排序前及最终注入前重检来源，不能仅依赖索引更新时的一次权限判定。

## 纠正与遗忘屏障

遗忘先建立阻止旧内容继续使用的屏障，再执行底层清理。采集投递、手动纠正与迟到结果都要与当前版本比较；过期结果不能把已失效事实重新写回有效上下文。

因此必须区分操作已接纳、内容已停用、清理已完成。单纯从搜索结果中暂时消失不能证明完整清理。

## 有界读取

持续任务引用最多读取三跳、二十个对象与三十二 KiB，游标绑定本人、工作与版本。关键词索引只保存工作卡和事件预览，不复制完整聊天或原生日志。

当前关键词查询返回最近写入的最多二十个匹配，避免对全部历史评分。少于三个字符时只查最近二百张卡。这些是持续任务搜索的当前边界，不能推断个人事实检索采用同一配额。

## 确定性首页与成本

首页读取根据本人关注、任务证据、来源有效性、个人日期和策略生成简报。读页面与刷新不需要额外整理模型；本人点击跟进或开始新话题时，才进入相应模型运行。

这限制了后台整理成本，也限制了摘要的语义丰富程度。未来模型整理、向量检索或共享项目范围应单独引入预算、权限与质量验收。

## 可验证的性质

用合成数据检查跨用户隔离、关闭后的注入行为、纠正与旧投递竞争、来源失效、迟到写入和重启。把事实保存成功、关键词命中和模型实际使用该事实作为不同指标，不从其中一个推断全部成立。
