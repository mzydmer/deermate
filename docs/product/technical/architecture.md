# 系统架构与设计边界

DeerMate 研究跨独立 Agent 会话、来源事件与个人设备的持续协作。核心设计是把模型的任务建议、程序的确定性接纳、设备上的原生执行和可复核证据分别建模。当前是研究 Alpha，完整持续闭环与比较实验仍待验收。

## 组件职责

| 组件 | 责任 | 关键边界 |
| --- | --- | --- |
| React 工作台 | 目标输入、状态、证据和本人决策 | 展示真实回执，不能由按钮状态授予执行权限 |
| Go 控制端 | 登录、身份、授权、版本、工作账本与投递屏障 | 主服务、管理和前端 API 的唯一后端边界 |
| DeerFlow 内部运行时 | 模型对话、持久 Router、无工具 Assessor 与任务适配 | 复用现有运行图和普通任务驱动 |
| 授权连接器与 Worker | 设备协议、项目接纳、原生进程、事件与产物 | 本机再次检查授权和版本 |
| 原生 Agent | 在获准范围执行一轮工作 | 保持原生会话身份，独立记录每轮结果 |

当前保留 Python 运行时、Worker 和桥接组件。Go 方向不意味着所有内部组件都已迁移。Hermesh 是可选生态桥接，不是核心系统的必选依赖。

## 一次工作的数据路径

用户提交目标后，Go 核对本人身份与输入版本，保存工作或操作。Router 在受限工具集合中组织建议；具体执行通过原有任务驱动进入授权连接器和 Worker。Worker 在设备上检查项目与权限，运行原生 Agent，收集结果与验证记录。工作台最终读取这些记录。

模型输出不能改变项目根目录、延长授权或将外部文字解释为发布许可。设备连通、任务接纳、执行结束和验证通过分别形成证据。

产品文档使用独立的只读前端路径。入口代理将 `/docs` 及其子路径交给前端，登录、任务、管理和其他后台接口继续经过 Go 的身份与权限检查；文档页面不读取私人运行记录。

## 状态与持久化

Go 使用现有 SQLite 保存账号、工作、来源、事件、决策、预算与动作记录；运行时继续使用自己的任务和原生 journal。跨边界持久化不是一个分布式数据库事务，因此发送屏障与原操作核对是必要的恢复机制。

当前存储面向可信单 owner、单实例及本地磁盘。多控制器协调、共享网络 SQLite 和生产多租户隔离不在已验证范围内。

## 可选调用链

调用链把一次工作的接纳、模型与工具调用、设备执行及独立验证关联起来，用于判断慢在哪里、哪一步失败，以及失败后是否重复派单。它使用标准 OpenTelemetry，开源部署默认关闭；接收后端可由自托管者选择。现有云端实例已接入 ARMS，应用不依赖云厂商 SDK 或账号。

![可选调用链：持久身份与跨进程关联](/deermate/docs/diagrams/observability.svg)

图 2：业务流之外的诊断数据。Go 和 Worker 分别保存首次关联；后台派单及受控中转恢复上下文。一个长期话题可以有多轮 Trace，原生会话身份继续沿用；中断后的恢复使用关联链接，不把已结束跨度重新打开。

遥测只包含操作、状态、合法身份、时间和实际提供的用量；默认不采集对话、记忆、命令、补丁或认证材料。独立验证单独记录，导出失败不会触发重新执行。业务 ID 是查询属性，不作为高基数指标标签。HTTP/MCP 明确标注客户端与服务端跨度，异步派单和执行使用生产者/消费者类型，便于兼容后端识别跨服务调用方向。

已于 2026-11-12 升级现有云端实例，并在 ARMS 查询到同一秘书会话的两轮真实模型调用，包括持久派单、记忆读取和模型耗时。四服务的设备执行树使用此前已验收的合成协议数据另行核对，能看到原生轮次和独立验证；这不代表重新执行了家庭设备或真实 Codex。

没有独立的指标、日志或 AgentLoop 评估管线。原生工具跨度只依据实际开始和完成事件建立，未提供的内部模型调用和用量保持未知。调用链可能因采样或导出故障缺失，任务账本与结果证据仍是事实依据。

## 设计取舍

- **复用原生会话**：保留执行上下文和历史结果，代价是必须处理忙碌、过时 head 与未知接纳。
- **程序决定接纳**：模型负责语义建议，身份、权限、预算和版本由程序检查，减少提示词承担的安全职责。
- **有界上下文**：采用范围引用和关键词入口控制读取成本，代价是语义召回与跨主题归并能力有限。
- **默认关闭自动执行**：先获得观察和手动接纳证据，再在明确授权与额度内开放自动处理。

## 信任与适用范围

模型供应方会接收相关提示词和上下文，应用与设备管理员也可能读到其管理的数据。worktree 用于隔离代码修改，不能代替操作系统沙箱。

系统不宣称无条件无人值守、任意服务免授权接入、通用端到端保密或新算法优越性。技术研究的可测量假设见 [研究问题与评估方法](/docs/technical/evaluation)。

## 界面实现边界

已于 2026-11-13 部署的组件化改造由 design.md 中的 YAML 生成 React、Go 共用的设计变量与配方，并生成 Tailwind 语义映射。React 基础组件包装既有 Radix/shadcn 原语；应用壳、输入区和详情面板组合成可复用布局，页面负责数据与权限条件。Go 管理页与工具扩展使用相同的生成配方。

静态门禁同时检查设计值和组件分层，并限制手写 CSS 的位置与预算。合成环境中的浏览器检查覆盖布局、主题、键盘和状态；它不证明真实设备可连接、模型已配置或任务已独立验证。组件陈列和旧组件合同宿主仅在显式测试开关下开放，正常生产环境不提供这些页面。
