# 默认可用的秘书与记忆设置

状态：Implemented，本地验收通过，既有云端实例已发布 `161fd29`。用户于 2026-11-04 明确要求「秘书与工作」默认直接开启，并在设置中展示记忆管理。本条覆盖 M4.5 的用户手动启用默认；不改变设备授权、来源 opt-in 或自动执行额度。

## 产品行为

- 设备 owner 登录后即可交代工作、查看工作和发送明确追问。首页移除独立启用开关和模型 ID 表单。
- 秘书复用用户已选对话模型，未选时使用模型目录首个默认模型。模型缺失或不支持当前受限客户端时，提供统一模型设置入口，不请求用户重复配置秘书。
- 首次投递前冻结模型，未知回执仍只核对原操作。读取首页不触发模型请求；管理员显式停用安装级服务时仍拒绝新投递。
- 旧「关闭持续秘书」只继续暂停其背景观察/自动行为；直接对话和手动工作不再受该旧开关阻挡。来源/规则和自动非零额度仍需本人明确设置，不自动恢复旧背景任务。
- 设置 → 记忆使用本人记忆管理：已保存内容、搜索、来源、修改、遗忘、采集开关。个人记忆和明确采集的当前选择保持，不自动读取历史或推断新事实。

## 实现与验证

Go 保留控制/执行权限和预算；交互可用性与背景设置分开。模型选择通过现有本人偏好和目录解析，能力检查不调用模型。角色、origin/CSRF、单 owner、冻结授权和未知不重发维持。

复用现有个人记忆组件替换设置里的上游记忆页，避免两份记忆主源。覆盖默认无配置、模型选择/缺失、旧背景暂停、只读不计费、回执冻结、设置来源/CRUD和账号隔离；Go 必需检查、前端生产构建、设计 token、文档门禁和浏览器验收分别记录。

本地结果见[专项收据](../verification/default-secretary-memory-2026-11-04.json)。默认规则在 Go 与 Python 窄适配器共同执行；模型能力元数据检查保留运行时的身份及 CSRF 对，不调用模型。

云端 28 项 HTTPS/账号/数据/API、46 项文档/资源和 17 项授权回归通过，原账号/记忆/历史及 auto=0 保留；[上线收据](../verification/default-secretary-memory-cloud-2026-11-04.json)。只读检查未调用实际 Router/模型/Native，线上视觉与真实设备闭环仍独立验收。
