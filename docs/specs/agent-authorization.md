# Agent 授权与连接管理

- **状态：** 用户已要求实现并上线；首期实现进入验收，部署状态以 STATUS 为准；不延长现有 SSH 授权
- **关联需求：** FR-002、FR-009、FR-010、FR-011、FR-013、FR-018；NFR-001、NFR-002、NFR-003、NFR-005、NFR-008
- **更新：** 2026-11-02

## 问题与目标

现有云到本机链路是手工部署的限时 alpha。授权截止时间、SSH key 到期、云端清理 timer、本机 connector 截止时间分散在不同配置中。到期后可能先出现 token 不可用，用户难以从页面理解原因。现有只读 doctor 可以检查连接，但不能证明 Codex 登录有效、项目可操作或容量充足。

新增「设置 → Agent 授权」，统一管理谁可调用哪台设备上的哪个 Agent、可以操作哪些项目、有效到何时。用户明确选择期限，页面展示授权、连接和执行就绪三个独立事实。任何模型、脚本或重连进程都不能自行扩大范围或延长授权。

本提案继承 [Go 控制端边界](../architecture.md)、[安全模型](../security.md)和 [UI 规范](../../design.md)。[ADR 0010](../decisions/0010-temporary-home-reverse-link.md)继续描述历史测试链路；本提案不将其 24 小时限制变成所有用户授权的产品限制，也不自动改写或恢复历史部署。

## 授权对象与边界

一条授权绑定 `owner_user_id + device_id + worker_instance_id + adapter_id + project_ids + permissions`。设备、Worker、Agent 分开建模：一台 Mac 可以有多个适配器，但安装了 Codex 不表示授权了所有 Agent。更换 Worker 数据库/设备身份必须重新配对，不能沿用旧任务身份。

首期只向现有单 owner 管理员开放可写管理，不开放普通账号执行权限。管理员身份不替代设备持有人的本机确认。将来共享设备、跨用户项目授权另行设计，不把当前全权 Worker token 当作租户隔离。

项目只能从本机显式登记并发布的项目清单中选择，不接受网页或模型提交任意本机路径。首期权限仅提供实际适配器能强制执行的操作：查询本人任务、提交任务、续接会话、修改指定项目、执行本机已登记验证命令、请求取消。读写模式必须由 Worker 和适配器共同落实；不能落实的选项不可勾选。Git 推送、创建 PR、合并、发布、邮件发送及任意 shell 不因本授权自动获得。

## 页面与交互

### 授权列表

入口为「设置 → Agent 授权」；工作台 Agent 摘要、任务执行器标签与连接错误均可直达对应授权详情。

| 列 | 内容 |
| --- | --- |
| Agent / 设备 | 适配器名、设备别名；可展开设备身份 |
| 授权范围 | 项目与关键能力摘要；禁止用“全部权限”掩盖实际范围 |
| 授权状态 | 待本机确认、配置中、有效、即将到期、已过期、已撤销、配置失败 |
| 连接状态 | 检测中、最近可达、离线、未知、检测已过时；附最近检测时间 |
| 到期时间 | 用户时区的绝对时间、时区与剩余时长；长期授权写“直到手动撤销” |
| 操作 | 查看详情、检查连接、修改授权、续期、撤销；根据实际状态提供 |

默认按需要处理的程度排序，过期/异常在前；不把旧的可达观测长期显示成绿色在线。没有设备不显示伪造数量，提供添加入口；检查失败保留既有数据及其观测时间。移动端按设备行展开细节，不压缩字号或依赖 hover。

### 添加授权

1. 页面生成短时、一次性配对请求。用户在本机 connector 中登录同一受信服务并确认请求；低熵显示码仅用于匹配核对，不能独立兑换凭据。请求绑定 owner、服务来源、设备公钥指纹、nonce 和短期有效期，限次验证并阻止重放。首期配对请求建议 10 分钟过期，与正式授权期限分开展示。
2. 本机发布已安装的适配器、已登记项目与支持能力；网页选择可授予的范围。云端不能枚举本机任意目录。
3. 用户明确选择期限，无静默默认值：1 小时、24 小时、7 天、30 天、自定义日期时间、直到手动撤销。快捷选项从最终确认时起算；自定义时间在提交时必须仍在未来。
4. 同一表单选择到期时的任务策略、提醒时间，显示设备、项目、能力、起止时间和时区的完整摘要。本机确认同一摘要的哈希/版本后才能生效。
5. 授权、设备策略与传输配置全部完成且只读验证成功后显示“有效 / 最近可达”；部分失败保留记录与明确失败步骤。配对成功但尚未检测时，显示“有效 / 未检测”，不能声称可执行。

页面不展示或要求粘贴原生 Codex 登录 token。原生模型登录继续留在设备；Worker/SSH 技术凭据通过受信配对流程管理，普通页面只展示引用、指纹、到期和轮换结果。

### 详情与续期

详情包含授权人、授权时间、设备/Worker 身份、项目和操作范围、开始/到期时间、到期任务策略、最近心跳与检测、当前连接故障、原生登录观测、并发用量、授权变更记录和相关任务入口。没有可靠探测的字段显示“未检查”，不运行模型来美化就绪状态。

点击续期先展示当前期限和新期限；提交后显示“待本机确认 / 配置中”，只有各执行端安装新版本后才更新有效期限。首期所有续期、长期授权、扩权均要求本机确认；设备离线可保存待处理申请，旧期限继续生效，不能把申请时间当成生效时间。撤销后的授权不能续期恢复，必须新建授权；过期授权可以发起重新授权，保留同一设备的历史引用但创建新有效版本。

后台轮换技术凭据不需要用户反复确认，但上限始终是当前有效授权；首次产品化不支持“自动延长用户授权”。

## 状态与时间语义

授权审批/配置状态与有效版本分开存储。续期申请失败或仍待确认时，原有效版本不被提前替换；收窄/撤销则先在 Go 接纳层拒绝新增越权操作，再同步设备。

| 维度 | 状态与来源 |
| --- | --- |
| 授权 | 以 Go 持久有效版本及服务端时间推导 active / expiring / expired / revoked；pending / applying / failed 属于变更申请 |
| 连接 | 经过鉴权、身份固定的 Worker 检查结果；传输握手成功单独不足以证明 Worker 可达 |
| 执行就绪 | Worker 存活、适配器可用、原生登录观测、项目权限、容量；每项单独包含 checked_at 与来源 |
| 技术凭据 | 正常、轮换中、轮换失败、已过期、待清理；不改变用户授权截止时间 |

初始参数建议：connector 每 30 秒发送有界心跳，90 秒无心跳标记离线；页面 15 秒刷新已有快照，按需执行连接检查并合并并发请求；只读连接检查沿用 15 秒请求期限与最多 2 秒清理。最后一次成功结果过 90 秒失效，显示“状态已过时”，不沿用在线结论。心跳和连接检查来源必须分开展示。以上均为待实测调优参数，不是现有能力。

有效区间为 `[not_before, expires_at)`；`expires_at = null` 只允许和明确的 `until_revoked` 模式一起出现。Go 与 Worker 都在操作接纳时校验，UI 倒计时只负责展示，不能决定权限。所有存储时间使用 UTC，展示使用用户 IANA 时区及 UTC 偏移；自定义时间遇到夏令时重复/不存在时要求明确选择或修正，不能静默偏移。

用户期限与技术凭据寿命分开。建议技术租约最长 15 分钟，实际截止取 `min(当前时间 + 技术租约, 用户截止时间)`；长期授权也使用短期技术租约。后台只能在有效且未撤销的授权版本内轮换。设备有本地绝对截止与单调时钟租约保护，时钟回拨不能延长；时间可信性不足或租约过期时拒绝新增执行，直到重新校验。

## 到期、撤销与运行中任务

到期立即拒绝提交、续接、回答原生表单和重启执行；不删除任务/审计记录。云端已经保存的历史任务与证据仍可按本人数据权限查看，远端新查询必须有仍有效的独立只读权限，不能借“查询”绕过撤权。

用户创建授权时必须看到并选择到期任务策略：

- **允许已开始任务完成（推荐）：** 到期前已实际开始的任务可在原任务硬时限内完成当前轮次和既定验证；队列中尚未开始的任务不启动。不得新增轮次、接受新表单授权或扩大能力。需要等待用户输入的任务在无授权时不能继续。结果在本机保留，之后可经新授权同步。
- **到期请求停止：** 本机按持久截止时间阻止排队任务启动，并请求停止运行任务。只有确认原生进程停止才能标记 cancelled；未知结果进入原有恢复/待核对路径。

撤销默认阻止后续操作并请求停止，可由用户明确选择让已开始任务在原硬时限内完成；对话框显示影响任务和选定策略。云端撤销立即落库和生效，本机及 SSH 清理另记确认状态。设备离线时显示“已撤销；设备清理/停止尚未确认”。健康连接下目标 5 秒内传播撤权；分区时对已经签发租约的最坏新增操作窗口为剩余租约时长，当前设计上限 15 分钟。页面和验收必须说明此界限，不能宣称全网瞬时撤销。

删除服务器 authorized key 不会终止旧会话，必须关闭对应 listener/session 并使 Worker 拒绝旧版本。先保留到期/撤销原因及审计，再清理可用凭据；用户先看到“授权到期”，而不是被缺文件错误遮蔽。

首期到期后不承诺自动从设备读取最新状态：旧链路关闭时结果留在本机，云端显示最后同步时间。若以后支持仅回传已接纳任务结果，必须单独定义窄权限通道，不能继续使用全权 Worker token。

## 控制端与 Worker 契约

Go 是用户授权唯一写入入口；Python MCP/SSH 仍是内部传输和任务集成组件，Worker 负责本机二次接纳。浏览器/模型不能直接写 controller.toml、SSH key 或 systemd timer。

```text
用户网页 → Go 授权记录/策略版本/审计
                    ↓ 持久 outbox，按版本幂等执行
             内部传输配置协调器 ↔ 本机 connector / Worker
                    ↓                    ↓
             SSH 有界技术租约       本机授权版本与截止
                    └──── 任务接纳校验 ────┘
```

原有全权 bearer 不足以表达用户/项目/Agent 范围，必须在正式开放模块前增加逐授权认证与 Worker 端强制策略：凭据绑定授权、设备实例、受众、操作范围、版本和到期。使用成熟库和标准认证机制，不自创密码协议。Go 内部调用携带真实用户/授权身份，MCP 不共享无区别的全 owner 权限；Worker 核对本机确认的范围，不能仅信任请求体的 user_id/project_id。

续期先准备凭据、安装新策略/传输期限，核对回执后原子切换有效版本；apply 失败保留原授权及其旧截止。撤权则反向处理，先拒绝新增再清理。outbox、端点回执和版本 compare-and-swap 使服务重启后可继续核对；旧 timer/迟到清理不能删除新版本凭据或杀死新 session。按版本命名并校验 active generation，不依赖易竞态的共享文件覆盖。

长授权连接可在网络恢复或重启后恢复传输，但必须重检策略版本、租约和固定设备身份；任何重连都不重放任务。历史 `instance_id:task_id` 绑定与幂等键继续保留。

### 数据模型

| 实体 | 关键字段 |
| --- | --- |
| Device | id、owner、display_name、instance_id、identity_fingerprint、registered_at、last_seen_at |
| AgentEndpoint | device_id、adapter_id、version、capabilities、各观测及其时间 |
| Authorization | id、owner、device/instance/adapter、project_ids、operations、duration_mode、not_before、expires_at、expiry_task_policy、active_version、revoked_at/reason |
| AuthorizationChange | request_id、expected_version、requested_policy、local_confirmation、apply_state、各端回执/失败原因；持久幂等键 |
| CredentialLease | grant_id、generation、issued_at、expires_at、fingerprint/secret_ref、rotation_state、cleanup_state；普通表不存明文私钥/token |
| ConnectionObservation | grant_id、source、checked_at、valid_until、各检查结果、稳定故障码；历史成功不会覆盖较新的失败 |
| AuthorizationEvent | owner/actor、动作、前后版本/范围差异、时间、结果、关联 request_id；不存秘密或原始任务正文 |

### 拟定 Go API

以下为拟定接口，不表示已存在。所有写操作使用既有会话、CSRF、owner 过滤、幂等键和并发版本保护；返回公开视图，不返回秘密。

| 接口 | 行为 |
| --- | --- |
| `GET /api/agent-authorizations` | 本人授权、有效版本、待处理变更、连接快照及 server_time |
| `GET /api/agent-authorizations/{id}` | 范围、时间、策略、观测、脱敏事件与任务引用 |
| `POST /api/device-pairings` | 创建一次性配对申请，返回脱敏摘要和短期请求期限 |
| `POST /api/agent-authorizations` | 创建待本机确认的授权意图；不返回 active 假成功 |
| `POST /api/agent-authorizations/{id}/changes` | 修改期限/范围/策略；`expected_version` 冲突返回 409 |
| `POST /api/agent-authorizations/{id}/checks` | 有界只读检查；不运行模型，不发测试任务 |
| `POST /api/agent-authorizations/{id}/revocations` | 先提交撤销、任务策略，再异步清理；返回 applied/pending 明细 |
| `GET /api/agent-authorizations/{id}/events` | 有界、可分页的本人授权历史 |

内部 connector 的配对确认、心跳、策略回执接口使用独立设备认证，不复用浏览器 cookie；具体凭据交换与标准票据格式在实现前完成协议评审。首期不接受任意 SSH host/port 的公开表单来生成服务端探测目标，防止将连接检查变成任意网络访问。

## 用户可读错误与提醒

错误优先级为授权 → 配置/凭据 → 网络 → Worker → 原生 Agent → 项目/容量。已过期时仍展示过期原因，即使凭据也已清理。

| 情况 | 页面提示与动作 |
| --- | --- |
| 授权到期 | “授权已于 … 到期，无法派发新任务。”；重新授权 |
| 凭据轮换失败 | “授权仍有效，连接凭据更新失败。”；重试连接配置，保留用户原期限 |
| Mac 离线 | “设备未连接，最后在线 …。”；连接指引，不误报 Codex 登录失效 |
| Worker 不可达 | “设备已连接，执行服务未响应。”；检查本机服务 |
| Codex 登录失效 | 仅有可信状态时显示“请在这台设备重新登录 Codex”；无探测时显示未检查 |
| 设备身份变化 | “设备身份与原授权不符。”；拒绝连接并重新配对 |
| 撤销未确认 | “云端已禁止新任务；本机停止/清理待确认。”；保留任务核对入口 |

提醒建议默认站内，在到期前 24 小时和 1 小时各一次；短授权只保留仍有意义的时间点，用户可调整或关闭。创建时已经处于提醒区间只显示就近提示，不补发多条。到期及异常有持久页面提示，不能只依赖 toast。按授权/有效版本/提醒阈值去重；通知设置不改变授权期限。邮件等外部通道只有在用户另行开启后使用。

## 实施顺序与迁移

1. **可见性：** Go 提供现有登记的只读公开视图，页面展示实际截止、最后观测与原因，先解决“看不见为什么断开”。已过期记录导入为 expired，不恢复、不生成可用密钥。
2. **可管理：** 落地 Go 授权/审计/outbox、版本化传输协调、本机确认、期限与任务策略；完成 Worker 按授权身份接纳后，才开放创建、续期、撤销写入口。不能用只改一个 TOML 时间的方式假装续期。
3. **日常使用：** 短凭据轮换、长期授权、connector 重启恢复、提醒与异常恢复。长期授权入口依赖本机持久撤权/租约执行和真实断线验收，不能提前出现可点击的空功能。

这是目标模块的分阶段交付次序。历史记录保留原任务和会话，不迁移 Native 登录、不增加公网 Worker 端口、不自动启动新模型任务、不拓宽项目。实施会替换历史限时脚本的配置职责，需另记 ADR，保留原有 ADR 的历史事实。

## 验收标准

以下均待实现与验证，不能当作通过记录。

| 编号 | 可观察结果与验证 |
| --- | --- |
| AUTH-01 | 用户必须明确选择期限；快捷/自定义/长期授权在页面、Go、Worker、传输端保持一致；边界与夏令时用可控时钟测试 |
| AUTH-02 | 授权/连接/执行就绪独立展示；过时成功不显示在线；不通过检查触发模型或任务；API + 浏览器验证 |
| AUTH-03 | 到期即拒绝新操作，排队未启动任务不启动；两种在途策略、表单/续接/验证边界用 Worker 集成测试 |
| AUTH-04 | 云端与本机双向强制项目/Agent/owner/操作范围；伪造 owner、越项目、重用全权 token 和实例漂移均拒绝 |
| AUTH-05 | 离线续期只创建 pending，不提前延期；失败仍执行旧截止；重试同一 request 不重复发放权限 |
| AUTH-06 | 并发续期/撤销、迟到回执、重启、旧 timer 运行均不复活已撤销权限、不删新凭据；故障注入验证 |
| AUTH-07 | 撤销后立即云端拒绝，健康链路 5 秒传播目标与分区 15 分钟租约上界独立测量；不得将请求当停止确认 |
| AUTH-08 | 到期错误优先于缺凭据；原任务/会话/证据保留，不自动重放；API 与持久数据库映射核对 |
| AUTH-09 | 提醒按版本去重，关闭提醒不改期限，列表和详情仍可见过期；可控时钟离线测试 |
| AUTH-10 | 一次真实 Mac↔云端短授权：用户选时、实际到期、session 清理、重新授权、断线与原任务核对；单独保留脱敏收据 |
| AUTH-11 | 浅色/深色、390px 手机/桌面、键盘、loading/空/失败/无权限/过时状态；按 UI 规范浏览器检查 |
| AUTH-12 | 私钥、Worker token、Native 登录信息不出现在公开 API/普通日志/页面；标准认证票据与重放/过期/错受众测试 |

## 首期实现与提案差异

首期实现 Go 管理页面/API、一次性配对、本机逐版本确认、期限/范围、待确认申请取消、撤销、最近心跳/Worker 观测、历史记录及出站 HTTPS 任务传输。实现选择见 [ADR 0014](../decisions/0014-user-managed-agent-authorization.md)，使用见[指南](../agent-authorizations.md)。

上文的 SSH 配置协调器/outbox、15 分钟技术租约是设计阶段的选项。首期改为既有 HTTPS 入口的 Go 持久请求队列，已投递操作至多交付一次；本机观测有效期为 90 秒，云端每次请求直接重查权限，MCP 凭据按授权版本变更。使用标准 TLS 和随机 bearer 身份，不开放 Worker HTTP。设备身份凭据自动定期轮换尚未实现。

首期自定义时间明确以 UTC 输入、按浏览器时区展示，避免静默处理夏令时歧义；浏览器提前到期状态可见，后台邮件/站外提醒、开机守护、共享授权、完整原生登录/容量探测仍为后续范围。页面不提供未实现的开关或伪造在线结果。

AUTH-01–AUTH-12 是完整目标验收，首期不得全量勾选；离线协议替身、浏览器和线上范围分别保留实际记录。原有授权不会被部署过程自动激活。
