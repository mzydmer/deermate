# 单机共同冷备与隔离恢复

- **Status:** Accepted; implementation and actual restoration pending verification.
- **Requirement IDs:** NFR-005–007/010、FR-007/023/028–032。
- **Tracking:** [Issue #4](https://github.com/mzydmer/deermate/issues/4)
- **Updated:** 2026-11-16

## 目标与范围

单个 SQLite 在线副本不能代表 Go、DeerFlow checkpoints/home、DeerMem/FTS5 与 journal 的共同恢复点。标准 single-host 命名 home 卷采用维护窗口冷备；归档还包括 bundle 配置，保存到原卷和 bundle 之外。保留原卷，只向独立 Compose 项目和新空卷恢复。

归档包含私人数据、密码哈希及密钥，保持私有权限，需另行加密与离机保存。校验和检测损坏，不能证明归档来源。外部 Worker/native 会话和项目、TLS 卷、独立环境/bind 凭据不在 home 快照内，运维者单独清点与核对。

## 生命周期与身份

先暂停来源和自动处理、核对在途工作，再关闭入口和所有 Go/Gateway/home 写入方。拒绝仍有其他容器写入同一卷的情况。停写后记录共同恢复点、快照 ID、不可变镜像及可得源码标签、快照工具源码身份、逐文件哈希、原操作/任务与未知状态。未知工作未明确确认清点时不发布快照；确认清点不等于取消或自动重试。

恢复先将输入归档复制到仅本进程持有的私有临时文件，再完整验证该对象；同一对象用于配置和 home 解包，原路径之后变化不改变恢复内容。验证包括必需组件、成员唯一性和父子文件冲突、规范路径、普通文件类型、大小、权限、所有者、时间、链接/设备字段及允许的 PAX 元数据。任一缺件、损坏或非法元数据在创建目标 bundle/卷前失败。复制中断的目标保留检查，不自动启动。

恢复必须使用带 restore-quarantine-v1 能力的控制镜像。隔离禁止新工作与自动派发，保留登录、本人读取与记忆搜索，并仅允许本人删除记忆和管理员撤销本人 Agent 授权。沿用原认证、CSRF、owner 和版本检查。删除同步调用确定性的内网记忆存储 apply，不调用模型或 Native；无法确认时仍冻结执行，待租期后仅以相同 operation_id 核对同一删除。创建/修改事实、批准/扩展授权、设备 poll/results 与其他写入仍拒绝。Go 四类后台队列、来源同步及 Gateway scheduler/MCP tasks/subagent batches/project summaries 关闭；MCP、遥测和外部应用网络关闭。原有未知身份和验证证据保留，不自动生成替代 Native 根或投递。

## 重新开放与限制

保持隔离期间，先核对原设备上的未完成执行和原操作结果。对照快照之后的遗忘、来源撤销、账号/密码、设备授权和密钥变更，逐项在恢复状态重新落实，再决定是否解除隔离。不能让两个控制面同时对原设备派发；新实例接纳新工作后不得用旧数据库覆盖。开关本身不构成新授权。

完整操作放在内部 [runbook](../backup-restore.md)，不增加客户接口或部署导航。新实现需独立评审合入，本次不部署生产、不续期权限、不运行真实模型/Native。架构取舍见 [ADR 0019](../decisions/0019-cold-snapshot-quarantine.md)。实际测试和运行结果以 STATUS/收据为准。
