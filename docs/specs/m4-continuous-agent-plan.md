# M4.5 实施 plan · 持续任务、事件调度与可追溯记忆

- **状态：用户已批准，P0 开始。** 2026-11-03 用户明确要求按 [spec](m4-continuous-agent.md) 与本计划逐步开发，完成验证后连续推进。
- **基线：** `19284cdee7a0bfcc060afd8bfd9bcc2859942f1f`；后续开始实现前重读 STATUS 和 Git，保留其他任务的工作。
- **更新：** 2026-11-03（America/Los_Angeles）。
- **原则：** 一个权威工作账本、一条既有执行链、一个对话一个原生会话。分阶段交付，每阶段完成验证后继续；只把真实完成的验收标为通过。

## 1. 顺序与阶段交付

`用户审核 → P0 契约 → P1 工作账本 → P2 执行闭环 → P3 GitHub observe → P4 追溯召回 → P5 产品入口 → P6 opt-in auto → P7 实机与发布`

P0–P5 构成第一个可用版本：能观察、建议和手动接纳。P6 增加用户明确启用的自动处理。P7 区分本地、真实供应方、真实设备和云端交付，不以 fixture 代替实机。

| 阶段 | 可审核的产物 | 主要依赖 |
| --- | --- | --- |
| P0 | 版本固定、接口探针、兼容与错误清单 | 当前授权/会话/DeerFlow 实现 |
| P1 | Go 工作/事件/决策/effect 模型与受保护 API | P0 |
| P2 | 独立 Router 的异步派单、手动闭环及回执核对 | P1、现有 journal/driver/relay |
| P3 | 单仓库只读来源、observe、已关联 Thread 直通/交回 | P1–P2 |
| P4 | 有界引用召回和本人关键词查询 | P1、现有记忆屏障 |
| P5 | 首页、工作详情、来源/规则配置与待处理项 | P2–P4 |
| P6 | 有界 auto、背压、程序监测及暂停 | P2–P5 验收通过 |
| P7 | 低内存/升级回退/有限真实验收及交付收据 | 前述阶段和实际可用授权 |

## 2. P0 · 固定契约与基线

- [ ] P0.1 核对当前 main、固定 DeerFlow revision、Go schema、已实现授权的实际交付状态；记录不改动的历史账号、任务和绑定。
- [ ] P0.2 在固定真实 runtime 中探测：持久 Router/输入回执、受限 Assessor、结构化 Worker 回报、规范 operation ID 接纳/查询、ordinary task driver、MCP 结果、动态授权 profile 和单会话 guard；列出能力版本。
- [ ] P0.3 确定已有后台跟踪/通知可复用部分。补窄接口而不增加公开 Python 路由、独立 scheduler 或 operator submit shim。
- [ ] P0.3a 固定 Router/Assessor/任务 Worker 的角色与 host 工具集隔离：Router 无执行原语，Assessor 无工具，任务 Worker 只操作原工作；真实用户指令可接纳，推断候选不能冒充明确指令。旧绑定对话不改变用途。
- [ ] P0.4 列出错误码、JSON schema、权限矩阵及预算可观测边界；明确哪些 Provider 能控制输出/重试。
- [x] P0.5 将 ADR 0015 在用户审核后标为 Accepted；若探针要求改变 spec 的产品边界，先记录具体差异供审核。

完成标准：离线 contract probe 通过；按 operation 查询可以证明“已接纳/未确认”，不会以新 POST 探测。不能满足的能力留明确阻塞项，不能绕过 journal。

## 4. P2 · 复用原执行链，先打通手动闭环

- [ ] P2.1 增加内部窄适配器：从规范 operation 读取 owner/目标、检查授权和绑定，调用现有 `ask_in_chat`/ordinary driver；不接受模型传任意 host、project path 或 Native ID。
- [ ] P2.2 Go 在派发前持久化发送屏障。适配器保存 operation→原接纳结果；查询原操作不需要模型参与。
- [ ] P2.3 将执行回报变成稳定事件，接回原工作、执行对话和首页；保留旧通知入口，不重复输出相同完成消息。
- [ ] P2.4 支持手动创建/加入对话、接纳候选、明确追问、核对原结果、暂停和请求停止。
- [ ] P2.5 故障注入：发送前崩溃、发送后回执丢失、响应落库前崩溃、迟到结果、head 变化、同时手动追问。
- [ ] P2.6 在原 DeerFlow runner 中装配独立 Router，限制工具及每轮工作量；派单/研判返回稳定 ID 后结束当前轮次，结果经 inbox 唤醒。禁止 Router 等待 Native 完成或调用 sleep/轮询工具。

主要复用点：`src/deermate/chat_sessions.py`、`session_middleware.py`、`briefing.py`、`relay.py`、`authorization.py`，以及 Go `briefing_actions.go`、`authorizations.go`。新的 runtime 适配模块不接管这些对象的主状态。

完成标准：实际 Go→Gateway→授权 relay/连接器→Worker 路径下，两轮共用一个 Native 根。用可延迟的 Assessor/Native fixture 验证在途时 Router 能处理下一输入、两种角色的工具边界和结果唤醒。先验证 CONT-05–09、CONT-14、CONT-20–21、CONT-23；真实 Codex 单独留到 P7。

## 5. P3 · GitHub 只读来源与 observe

- [ ] P3.1 实现固定仓库 GitHub REST 客户端、只读 secret_ref、ETag/速率限制和超时；禁止任意地址、重定向泄露 token 及模型生成 API 路径。

- [ ] P3.3 实现重叠轮询/分页游标、去重、编辑、删除/不可读区分和自有事件回环过滤；超限保存原因并停止推进游标。
- [ ] P3.4 确定性预筛后把未归属候选送 Router；其异步启动无工具 Assessor，对固定批次研判，结果事件回 Router。严格解析输出，保留输入/规则/来源/model/prompt 版本和依据。

- [ ] P3.6 已关联 Thread 在 Go 重检订阅后直通原工作队列；原范围续接不重新调用 Router，越范围的结构化 handoff 才交回路由。补充上下文不自动启动新 Native 轮次。

完成标准：HTTP fixture 覆盖 429/403/404、同秒修订、分页中断、响应丢失、凭据失效和规则变更。可计数假模型证明 observe 不创建工作执行会话/Native、不对外发消息；已绑定事件直通时 Router 调用为 0，handoff 恢复路由；覆盖 CONT-02–04、CONT-07、CONT-10、CONT-13、CONT-20、CONT-22。

真实 GitHub 凭据仅在已明确允许的仓库与只读范围内使用；不能借研究时 Codex 的 GitHub 连接给产品配置凭据。

- [ ] P6.1 规则区分自然语言条件与机器范围；auto 必须本人明确启用并填自动额度，首次默认 0。

## 9. P7 · 有限实机验收与发布

### 本地自动化

- [ ] Go 改动运行 `go mod verify`、`go vet ./...`、`go test -race ./...`、无 CGO 构建；记录实际工具链和输出。
- [ ] Python 改动先跑相关测试、Ruff/wheel，再按仓库要求做回归；固定 DeerFlow 图/驱动/SQLite 适配契约独立验证。
- [ ] 前端执行 TypeScript、生产构建、共享 token 检查和实际浏览器检查。
- [ ] 部署契约有变更时验证固定 Helm/Compose/单机/HTTPS；证据映射 CONT 编号，不预设通过数量。

### 低内存与恢复目标

- [ ] 在合计现有容器限额的独立 Compose 环境，用 1,000 个合成工作、10,000 个有界事件，验证分页/FTS/引用的索引计划和存储上限。
- [ ] 预热后对工作列表/详情/引用读取做 100 次、并发 1 的测量；初始目标 p95 ≤ 300 ms，且无整份历史扫描。记录主机、数据量及冷读结果，未达到时修正设计/索引，不改成未经证明的性能声明。
- [ ] 测量后台积压/限额时的容器内存和 UI 可用性；无 OOM 仅代表该工作量。真实 2 GiB 云主机另测，不由本地容器限额推断。
- [ ] 实际执行新增 schema、启动重启、停用模块和兼容回退；保留原账号、模型文件、记忆和原生绑定。未知操作不得被回退清空或重放。

### 真实闭环

- [ ] 确认目标仓库只读权限、实际供应方模型配置及有效的本机项目授权；缺少时记录具体前置，不恢复历史过期 SSH。
- [ ] 使用明确标识的测试 Issue/PR 或允许跟踪的真实对象，观察一次新增变化并接纳一项工作；最多 5 次后台研判派发和 2 个 Native 轮次，其内部模型用量另记。
- [ ] 确认两轮 Native 根/工作区一致，补丁范围、独立验证、来源追溯和首页状态对应；原结果核对不新建任务。
- [ ] 默认不向 GitHub 写入，测试对象由用户或另有明确权限的操作员准备。只读接入成功不能当作 PR 自动维护验收。
