# M4.4 · 有记忆的私人秘书与今日简报

- **状态：Proposed，待产品评审；本轮仅规格设计，没有功能实现或部署。**
- **版本：** 0.1
- **更新：** 2026-10-29
- **需求：** FR-001、FR-015、FR-018、FR-022，以及新增 FR-023–FR-028；NFR-001、NFR-003、NFR-005、NFR-006
- **关联：** [设计规范](../../design.md)、[会话关联](m2-chat-session-binding.md)、[架构提案 ADR 0013](../decisions/0013-memory-backed-personal-briefing.md)

## 1. 产品目标

用户打开 DeerMate，就能感受到秘书记得自己：知道怎么称呼自己，记得正在推进什么、长期关注什么，知道哪些事情有了变化，能把下一步准备好。

首页应在约 30 秒内帮助用户回答：

1. 我之前关心的事情，现在有什么值得知道的进展？
2. 哪些事情需要我回应，哪些可以继续交给助手？
3. 我可以从哪个历史对话接着做，或开启什么有价值的新话题？

**首期完成标准：** 一个真实用户能完成“表达关注 → 秘书记住 → 获得有来源的首页简报 → 一键跟进原会话 / 开启新话题 → 纠正或忘记记忆”的完整闭环。

这里的 Session 指 DeerMate 对话；Codex/Claude 的原生会话称为“执行器会话”。记忆可以在获授权的对话间提供上下文，但不会合并、复制或替换执行器会话。

## 2. 当前基线与缺口

| 当前事实 | 对本次设计的影响 |
| --- | --- |
| 首页已有目标输入、最近对话和真实后台任务；任务查询限最近 20 个对话 | 能复用任务证据与导航，但不能用“最近 20 条”代表全部长期关注 |
| 首页使用统一欢迎文案，没有个人称呼、个人时区和今日关注主题 | 需要增加用户资料及个性化简报读模型 |
| Go 用户资料现有 email/角色等字段，没有 display_name；偏好接口尚无 timezone | 称呼和时区是待实现字段，不能宣称已有用户名配置能力 |
| 当前最小部署显式配置 `memory.enabled: false` | 上线前需要设计个人启用流程和数据迁移，不能直接打开全局记忆并扫描全部历史 |
| 固定 DeerFlow 已有按用户的记忆管理、检索及事实 CRUD 抽象 | 优先复用；本项目尚未验证本次所需的启用、更新、删除和隔离契约 |
| Go 负责登录、管理及前端 API；内部 Agent/Worker 保留 Python | 新个人资料、关注主题、简报及动作接口继续由 Go 对外提供 |
| 一个对话固定关联一个执行器会话、自动命名/改名已上线 | 首页跟进和新话题必须保持这一约束 |

参考实现：[首页](../../frontend/overlay/src/components/deermate/desk.tsx)、[Go 边界](../../backend/internal/controlplane/runtime.go)、[用户模型](../../backend/internal/controlplane/store.go)、[部署配置](../../scripts/ack_deploy.py)。上游核对基于项目已固定的 `a1b89d0432de4e45adc59f512cb25bb386ea1e51` 源码；源码存在能力不等于 DeerMate 已完成接入。

## 3. 首页体验示例

以下是设计示例，文字与数量仅用于说明交互，不是当前系统已生成的简报。

```text
上午好，小林。

你关注的事情有两项新进展，还有一件事等你决定。

今日关注

DeerMate · 继续你的私人助手项目
你之前关注的会话绑定已经完成验证。下一步可以讨论记忆首页的设计。
来自《私人助手开发》及任务验证记录 · 08:20 核对

你关注的开源项目
你订阅的仓库发布了新版本，其中有一项与你关注的功能相关。
来自已连接的 GitHub · 07:50 同步
［查看变化］ ［开始分析这个版本］

一个待决定的问题
上次讨论的两个首页方向还没有定下来。
来自《首页设计》· 昨天留下的事项
［继续这个对话］ ［今天先不看］

你可能想聊
“比较这个新版本对当前项目的影响”
```

未连接 GitHub 时不显示示例中的发布进展；可以显示“你之前关注这个项目，可以发起一次公开资料调研”，明确这是一项建议。

## 4. 首页内容与布局

沿用 `design.md` 的中性配色、字体、间距和现有对话组件。首屏以自然语言、清楚的列表和操作为主；辅助任务详情按需展开。

| 区域 | 展示内容 | 首期约束 |
| --- | --- | --- |
| 问候 | 个人称呼、当地时段、日期；一句与当前情况相关的开场 | 没有称呼时只说“上午好”，不从 email 猜真实姓名 |
| 今日关注 | 新进展、待回应事项、用户设定的近期目标 | 默认最多 3 项；有多少证据展示多少，不凑满 |
| 可能感兴趣 | 相关的新问题、调研方向或下一步建议 | 最多 2 项；每项解释推荐原因 |
| 自由输入 | 直接向秘书交代新目标 | 保留当前入口，不要求用户先选推荐项 |
| 次级入口 | 最近对话、全部任务、记忆与关注管理 | 历史记录和任务证据仍可独立查看 |

每条进展包含：关注主题、简短结论、变化/待办、来源、来源时间、核对时间、主要动作。不能只给一段无法追溯的“秘书口吻”。

支持浅色、深色、390px 移动端和键盘操作。卡片只在实际需要分组时使用；状态有文字，不能只依赖色点。日期和时间使用统一用户时区。

## 5. 称呼、时区与“今天”

- 新增 Go 个人资料 `display_name` 与 IANA `timezone`；现有账号 ID、密码、角色和历史归属不变。
- 称呼使用用户设置的名字或明确要求的称呼；没有时可在首页内轻量设置，不阻塞使用。
- 时区优先使用已保存设置，其次使用经校验的浏览器时区；无法确定时使用 UTC 并明确标注。云服务器地域不决定用户的“今天”。不需要定位权限。
- 问候默认：05:00–11:59“上午好”，12:00–17:59“下午好”，其余“晚上好”；规则按用户当地时间计算。
- 用户修改称呼/时区后，首页与后续简报立即采用新值。个人资料是称呼的唯一事实来源，语义记忆不保存另一份相互冲突的姓名。
- “你离开后发生了什么”基于上次已读简报的来源版本；不能把每天重复展示的旧事项说成新进展。

## 6. 秘书记住什么

记忆、关注主题和执行证据具有不同职责。

| 类型 | 示例 | 写入依据与使用范围 |
| --- | --- | --- |
| 个人资料 | 称呼、时区、语言 | Go 资料/偏好，用户可直接修改 |
| 稳定偏好 | 喜欢简洁回答；希望先看结果 | 明确表达可记住；推断项先作为候选 |
| 项目与长期目标 | 正在做 DeerMate，希望低成本自托管 | 限定用户/项目；可关联多个历史对话 |
| 关注主题 | 持续关注某个开源项目或竞品 | 用户主动关注，或确认秘书的建议 |
| 对话摘要与未决事项 | 上次决定用 Go；首页方向尚未确定 | 引用原对话、时间和决定；不复制全部历史 |
| 进展与结果 | 任务完成、验证失败、PR 有新状态 | 以任务/来源的可核对记录为准，记忆只保存引用与摘要 |

“帮我查一次某个产品”可形成短期事项，不直接推断成长期爱好。“以后持续关注这个项目”或点击“关注”才能形成长期关注。助手自己的回答、重复推荐、验收对话和系统通知不能当成用户的新偏好。

项目约束需要保留适用范围和演进。例如“此项目主后端改用 Go”替代早期对应的 Python 控制端选择，但不会抹掉仍然存在的 Python Worker 集成事实。

### 写入与演进

1. 从获授权的用户表达、明确关注操作、实际任务事件提取候选；保留来源定位。
2. 显式的低敏感偏好/目标可在个人记忆已开启后直接记录，并可在“记忆与关注”中查看；低置信度推断先留在候选区，不进入确定性问候或进展陈述。
3. 相同实体/范围/事实去重；后来的明确更正优先于旧偏好。不同项目的选择不能互相覆盖。
   “明确表达、执行证据、推断”是可解释的来源等级，模型自报的置信分数不当作已校准概率。
4. 每条事实保留 `observed_at`、`valid_from`、`last_verified_at`、来源及版本；被替代的事实退出当前检索，历史演进仍可解释。
5. 用户更正、任务新事件或已授权来源的新版本触发重整；秘书自己的简报输出不再进入提取队列，避免自我强化。

### 生命周期与遗忘

- 用户可以查看、纠正、删除单条记忆，取消主题关注，或关闭长期记忆。
- 删除后立即停止检索/注入并失效相关首页缓存；待写入的旧提取任务必须检查删除版本，不能把内容写回来。
- 失效范围包含事实、共享用户/历史摘要、对话摘要和提示词缓存。provider 不能按来源重整共享摘要时，先停用受影响摘要，再从剩余有效来源重建；不能只删事实文件却继续注入旧摘要。
- 保留必要的来源 ID/删除版本以阻止同一历史消息被再次提取，不在删除标记中保留原事实正文。用户新的明确“请记住”可以产生新的记录。
- 删除记忆不等于删除原对话；清除对话/回收站也不是清除原生 Codex 会话。界面说明影响范围。
- 来源被删除或失去权限后，不再使用其摘要和引用；如果同一事实还有独立有效来源，可继续保留。归档对话默认不进入首页主动跟进。
- 完成的短期事项退出今日关注。建议默认短期关注 14 天无互动后淡出；显式长期关注、有效偏好不因沉默自动删除，可提示复核。
- 备份保留期和恢复流程要记录删除版本，避免恢复后重新展示已遗忘内容；不承诺即时清除离线备份或第三方模型留存。

## 7. 今日进展从哪里来

**记忆决定关注对象；新的证据决定进展。**

首期来源：当前用户自己的对话、未决事项、后台任务状态、独立验证结果、执行器关联及用户设置的关注。下一期增加单独接入的 GitHub/公开资料来源；邮件和日历仍需各自接入和授权。

这里的历史对话指本人在 DeerMate 已拥有或明确选择导入的记录。执行器提供当前链路已授权的结果/状态；读取 Codex/Claude 桌面客户端的全部聊天、本机目录或新的私人来源，不属于默认历史回填范围。

每项首页陈述需要关联证据，至少记录：`source_type`、`source_id`、`source_revision`、发生时间、最后核对时间和可访问的原记录。

| 情况 | 首页表达 |
| --- | --- |
| 有新任务结果及验证记录 | “这项任务已完成，配置的验证通过”，可查看证据 |
| 只有执行者完成声明 | “执行已结束，结果尚待验证” |
| 来源已同步且没有变化 | “截至 08:20 暂无新进展” |
| 只有历史记忆 | “你上次关注……；最后已知状态是……”，不称为刚发生的新消息 |
| 来源失联/授权过期 | “更新暂未核对”，保留最后已知时间，提供恢复连接入口 |
| 历史说完成，新记录显示复验失败 | 显示最新失败并说明是后续变化，不继续沿用旧的完成结论 |

新鲜度按来源定义，不能用“简报刚生成”代替“来源刚核对”。首期建议任务状态超过 5 分钟未核对标为待刷新，外部公开资料超过 24 小时未同步标为可能过期；这是待校准的产品默认值，不是现有 SLA。

## 8. 怎样决定今天先展示什么

先过滤权限、删除/静音、来源有效性和明显过期内容，再排序：

1. 当前用户需要处理的阻塞、失败、明确日期到期事项。
2. 已明确关注的目标出现实质变化，尤其是上次已读之后的新结果。
3. 未完成且与今天/近期目标相关的事项。
4. 有明确关联与推荐原因的新话题建议。

同一任务的多个通知、同一执行器会话的多轮结果，汇总为一条主题进展。多个对话指向同一个项目时可归并展示，但必须保留各自的对话入口，不能自动合并会话。

“今天先不看”只暂停该项到用户当地下一天；“不感兴趣”降低/抑制该建议方向；“不再关注”才取消长期关注。反馈可撤销。已读且无变化的内容不重复包装成新发现；没有合适建议时不展示推荐区。

## 9. 首页动作：点击之后具体发生什么

动作文字应准确表达副作用。首页卡片是入口，执行仍走现有对话/权限/任务链路。

| 按钮 | 明确行为 | 会话与执行器规则 |
| --- | --- | --- |
| 查看原会话 / 继续这个对话 | 打开对应历史对话，定位相关进展，准备上下文；不发送消息 | 保留原对话及绑定 |
| 一键跟进 | 把卡片已展示的跟进问题发送到原对话，返回可查看的跟进结果 | 首期使用受限的秘书只读跟进能力；不派发 Native 编码任务 |
| 继续执行：具体下一步 | 例如“继续执行：补充登录测试”；点击前展示项目、执行器和具体工作范围，点击后提交一轮有界任务 | 必须续接原绑定、使用现有项目权限；不创建新 Native 根会话、不增加权限 |
| 查看结果 / 查看进行中任务 | 打开既有证据或任务状态 | 不创建重复任务，不重新验证代码 |
| 开始这个话题 | 创建新对话并发送已展示的初始问题，携带最小必要的记忆摘要与来源 | 首条消息按已有规则命名；不复制旧执行器绑定，首期只读分析/调研 |
| 处理待确认事项 | 打开原任务的输入/审核/恢复入口 | 不代替用户授权，不自动回答原生权限请求 |

“一键跟进”和“开始这个话题”的问题、目的、来源范围在点击前可见；长问题可以展开。点击即代表发出该问题，不再弹一个重复的“确认开始”框。入口同时保留“只打开看看”。

新话题的首条用户消息仅包含被点击的问题；记忆摘要和来源引用通过内部上下文传递，不伪装成用户写下的正文。名称按这个问题生成，避免把背景资料变成标题。采集侧知道它来自简报建议的采用，不因此反向推断出新的长期偏好。

**进度跟进示例：**“根据《私人助手开发》的最新任务和验证记录，整理会话绑定的进展、未完成事项和建议下一步。”这会查询既有证据并回答。

**任务续接示例：**卡片显示“继续执行：为登录失败场景补充测试 · DeerMate 项目 · 沿用 Codex 会话”。用户点击后即可提交这项已展示的工作，复用既有项目权限、独立验证和任务跟踪，不再要求把相同目标复制到聊天框。不确定下一步时只提供进度跟进/进入对话，不显示含糊的“自动处理一切”。

只读跟进必须由服务端动作能力限制实现：允许读取本人对话/任务和明确支持的只读资料工具；不暴露 Native submit/continue、shell、文件写入、发信、发布、合并等能力。不能仅在提示词里写“不要修改”。这是待实现的新运行能力配置，不是对当前通用 Agent 的既有保证。

能力由服务端 intent 绑定，并在运行接纳和实际工具调用处检查；隐藏工具名称也不能替代执行门禁。只读范围针对本次首页动作，用户之后在普通对话里提出的新要求仍按既有角色/项目权限判断，不永久把原对话改成只读。

任务续接属于独立动作类型：服务端重新核对原会话最新终态任务、绑定、项目策略和执行权限，限定一个 intent 只提交一轮。正常执行权限已满足时直接运行，不增加重复确认；需要额外授权、恢复或人工输入时进入原有处理流程，记忆中的偏好不能替代授权。

历史会话忙碌时，按钮转为“查看进行中任务”；存在恢复/输入/关联冲突时进入对应处理页。项目或执行器发生变化时进入新话题路径。绝不静默换绑、创建替代 Native 会话或把两个原会话合并。

### 动作幂等与不确定结果

- Go 签发与当前用户、卡片版本、动作类型、目的会话及 incarnation 绑定的 `intent_id`，只接受服务器保存的规范动作。
- 模型只提议候选动作，不生成可直接执行的 URL、原生会话 ID、命令或授权。
- 双击、重试、多设备点击同一 intent，返回同一个创建/跟进结果。已执行后按钮显示“查看跟进结果”。
- 消息/新对话提交前记录尝试；超时只核对已有结果，不自动重发。如果无法确认，显示“结果待确认”。
- 来源、权限、目标 incarnation 或会话状态已变时，返回最新卡片/冲突说明；不能照旧执行过期动作。

## 10. 系统职责与数据契约

推荐架构仍遵守 Go 主后端方向，见 [ADR 0013](../decisions/0013-memory-backed-personal-briefing.md)。

| 组件 | 负责什么 |
| --- | --- |
| Go 控制端 | 用户资料/记忆开关、关注主题、证据索引、首页排序、简报快照、动作 intent/幂等、公开 API 与鉴权 |
| DeerFlow 记忆适配层 | 复用选定本地记忆 provider 的提取、更新、检索、事实管理与上下文注入；服从用户策略与删除版本 |
| 既有任务/会话存储 | 对话、执行器关联、任务生命周期和验证证据的事实来源 |
| 简报整理器 | 把已授权且可引用的事实整理成自然语言及候选问题；不能执行动作或修改任务状态 |
| React 首页 | 展示快照、来源/新鲜度与动作状态；沿用现有对话、任务详情、改名和设计 token |

不另造第二套通用记忆/向量系统。语义事实以 provider 为内容主源；Go 保存产品实体、策略、索引及有版本的展示投影。provider 不支持的更新/删除/用户隔离能力必须先补齐适配验收，不能悄悄换成全局桶操作。

### 核心实体（拟议）

| 实体 | 主要字段 / 约束 |
| --- | --- |
| PersonalProfile | owner、display_name、timezone、locale、memory_enabled、proactive_enabled；由本人管理 |
| MemoryReference | provider_fact_id、owner、scope、kind、source_refs、confidence、explicitness、revision、删除/替代状态；不另存一套竞争的事实正文 |
| AttentionTopic | owner、项目/主题、goal、关注方式、status、priority、related_threads、source_refs、snoozed_until、last_seen_revision |
| EvidenceRecord | owner、来源 ID/版本、发生/核对时间、访问策略、关联主题；执行状态以来源为准 |
| BriefingSnapshot | owner、local_date、timezone、locale、memory/data/policy revisions、generated_at、items、suggestions、source_as_of |
| ActionIntent | owner、snapshot/item、type、规范问题、目标 thread/incarnation 或新话题、范围、有效期、idempotency_key、提交/核对状态 |

所有检索先按 owner/项目授权过滤，再做相关性选择。默认记忆上下文预算建议不超过 1,500 tokens；超出时选取相关事实和引用，不把全部历史拼进提示词。

### 对外 API 方向（拟议，均由 Go 提供）

| 接口组 | 作用 |
| --- | --- |
| `GET/PATCH /api/me/personal-profile` | 称呼、时区、个人记忆及主动建议设置 |
| `GET/PATCH/DELETE /api/me/memories/...` | 查阅、纠正、遗忘；对应 provider 的受限操作及删除版本 |
| `/api/me/attention-topics/...` | 主动关注、暂停、完成、取消关注及反馈 |
| `GET /api/me/briefing` | 只返回本人已有快照/确定性事实回退；不发起模型或 Native 任务 |
| `POST /api/me/briefing/refresh` | 并发合并刷新；只同步已授权来源、按预算重整 |
| `POST /api/me/briefing/actions/{intent_id}` | 校验用户、状态、版本后执行规范动作；返回原会话/新会话和结果引用 |

路径是待实现契约，不表示现有接口可调用。浏览器不能传另一个 owner 决定作用域；当前普通用户的只读执行限制不因首页升级而解除，无执行权限时展示可查看的入口。

## 11. 生成、刷新与资源预算

首页读取不启动编码 Agent、不运行验证命令、不默认全网搜索。结构化任务进展可直接形成确定性文案；模型可用时，再整理表达和生成有理由的新话题。

触发源：用户明确更新关注/偏好、任务产生实质事件、已授权来源出现新版本、用户主动刷新。事件按用户合并，只有相关数据版本变化才重新生成；问候随当地时间变化不消耗模型调用。

首期建议默认预算（待压测/成本验收后校准）：

- 单机记忆/简报后台整理并发 1；优先保证正在进行的用户对话。
- 每活跃用户每天最多 2 次模型简报整理，记忆提取最多 10 个合并批次；用户主动聊天的计费与此分开。
- 每批整理最多 8k 输入 / 1k 输出 tokens；上限由实际模型窗口和配置取较小值。展示估算，不把估算当账单。
- 相同来源版本和记忆版本复用结果；来源核对后无变化，不触发新模型摘要。
- 同时设置实例级每日调用/tokens 上限；用户预算不能绕过实例预算。未配置计价信息时，费用显示未知。
- 限流、模型未配置或额度不足时，继续显示有来源的任务/关注列表和旧简报的时间，不阻塞首页。
- 使用既有应用进程与 SQLite 持久化轻量整理队列，首期不要求新服务器、常驻向量服务或外部记忆 SaaS。

开启“主动整理”后允许上述有界后台处理；离开应用仍持续轮询外部服务、每日固定推送或发送通知，属于后续独立的关注来源/调度设置，本规格不自动创建这些任务。

## 12. 数据边界与用户控制

记忆开关与主动建议开关分开：可以记住偏好而不展示主动话题，也可以关闭长期记忆，继续查看原有任务进展。首次升级先说明使用范围，提供“开启个人记忆 / 稍后”的轻量入口；不会自动回填全部历史。

首期历史导入建议：用户选择近期 30 天的普通对话及明确关注项目，小批处理、可查看进度、可取消。静态演示、带验收元数据的测试会话、系统/通知消息不作为用户偏好来源；导入不能重放历史工具调用。

验收排除依据可信的来源/运行元数据或用户选择，不仅因为标题里出现“测试”就排除真实工作。后台任务在入队时固定 owner/策略版本；写回前重新检查账号、记忆策略和来源权限，不借用后来登录的另一个用户身份。

明确排除密码、API Key、短信验证码、认证 Cookie/私钥等认证材料。首期不自动沉淀健康、财务等高敏感个人信息。使用业务字段白名单、已知格式拦截和保守采集；不能声称能完美识别任意文本里的秘密。

关闭/撤权/删除要同时影响后台提取、检索、提示词注入和首页缓存。用户可看见“为什么记住/推荐、来自哪里、怎样修改/忘记”。关闭长期记忆不会承诺清除仍在进行的聊天上下文或第三方原生会话。

关闭后仍可管理或清除本人已有记忆，但不将其用于 Agent 个性化或首页推荐。主动建议关闭后，不自动生成/展示新话题；用户主动提出的问题仍按普通对话流程处理。

继续使用 Go 登录、CSRF、角色及会话撤销；新增用户自助接口只作用于本人，不能给管理员列表附带他人的记忆。缓存、前端 query key 和后台任务包含 owner/版本，退出登录或切换账号后清除旧展示并中止旧请求。

外部网页/仓库/邮件/其他 Agent 的内容是参考资料，不能授权动作、提升可信等级或写入“用户偏好”。模型服务接收哪些记忆片段应可解释；本地存储不等于云模型无法读取传入的片段。

## 13. 空状态、失败与冲突

| 情况 | 用户看到什么 / 可以做什么 |
| --- | --- |
| 新用户、无记忆 | 问候 + “告诉我正在推进或关心的事” + 最近对话入口；不虚构个性化内容 |
| 记忆关闭 | 任务进展照常显示；明确个性化建议尚未开启 |
| 关注主题尚无更新 | 诚实显示最后已知状态，可继续原对话，不制造“今日新变化” |
| 部分来源失败 | 分项显示时间/失败，不把全部首页变成错误页，也不显示伪造的零项 |
| Worker 离线/权限过期 | 能查看历史结果；不能声称仍在线，不能自动续期或新开执行器替代 |
| 原会话删除/归档/变更权限 | 移除过期的跟进入口；需要重建上下文时明确是用户发起的新对话 |
| 旧会话多个 Native 关联或状态不明 | 进入原记录检查，沿用 FR-022，不自动择一或重发 |
| 记忆互相矛盾 | 优先最新明确更正并展示适用范围；无法判断时不据此给确定性建议 |
| 后台任务超时/重启 | 通过事件/版本/intent 核对已有结果；不循环重算或自动重发用户消息 |

## 14. 实施顺序与迁移

**第一版 M4.4 必须交付完整首页闭环：**

1. 资料/时区、个人记忆策略、provider 适配和来源/删除契约；记忆与关注管理入口。
2. 基于本人已有对话/任务建立关注主题与增量证据投影；处理历史导入与测试数据排除。
3. 今日关注、可解释的新话题、来源时间和空/失败状态；保留自由输入。
4. 一键只读跟进、范围明确的原任务续接、创建并发送新话题、状态重检和幂等；保留原生会话绑定。
5. 用真实用户流程验收记忆更正/遗忘、首页个性化、原会话跟进和新话题命名。

**第二版：** 明确关注的 GitHub/公开资料增量同步，来源粒度授权与频率/费用设置；有实质变化才形成新卡片。

**后续：** 更多个人来源、固定时间简报和通知、长期效果评估。邮件发送、发布/合并、无条件无人值守、自动跨项目执行、Claude 执行适配器不纳入本次记忆首页范围。

升级先备份应用 home、Go 数据库和 provider 状态；保留旧首页开关。新读模型可重建，事实/用户反馈/删除版本不能丢失。回退到旧首页不能重新启用已关闭记忆或恢复已遗忘内容。

## 16. 本稿建议的产品决策

默认采用：**明确关注优先、可信进展优先、首屏最多三件事、推荐最多两个、点击才开始跟进/新话题、个人记忆可查看可撤销**。

第一版从现有对话和任务获得价值；外部消息只在来源已连接且核对成功后进入“新进展”。预算、保留时长和新鲜度阈值均为本稿建议值，实施前校准。本文经评审后再拆实现任务，不因文档落库而开启记忆、回填历史、运行模型、创建监控或部署新功能。
