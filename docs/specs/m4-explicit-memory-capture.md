# M4.4b · 从新对话接纳明确记忆指令

- 状态：已实现并本地验收，2026-11-02；未升级既有实例或云端。
- 需求：FR-023、FR-028；完整 M4.4 的自动提取、简报与项目来源标准继续保留。
- 关联：[基础记忆](../personal-memory.md)、[完整规格](m4-personal-memory-briefing.md)、[ADR 0013](../decisions/0013-memory-backed-personal-briefing.md)。

## 产品行为

在“个人设置与记忆”中单独开启“从对话保存明确记忆”。既有账号默认关闭，长期记忆关闭时不采集。之后在普通对话发送“请记住：我偏好简洁的中文回答。”，这条明确个人偏好由已接纳的原消息保存到现有记忆列表，显示原对话入口；后续聊天复用既有召回。关闭、纠正、遗忘和来源删除继续生效。

这一阶段用确定性规则接纳用户明确的记忆指令，不调用提取模型，不推断爱好，不生成第二份用户陈述。支持 `请记住：` / `记住：` / `Remember:` / `Remember that ` 加上明确的个人偏好、长期目标或学习背景。一次性请求、疑问、引用/附件/混合消息、项目约束、改写旧偏好的指令不自动入库；后者使用现有纠正入口。语义提取、自动归并和模型作业预算仍为后续范围。

## 接纳与来源

1. Go 在本人正常 POST `/api/threads/{id}/runs` 或 `/stream` 前，检查当前开关并保存内存中的策略/遗忘版本；仅检查有 ID 的单条纯文本 human 消息，不修改转发正文。
2. 仅在运行时返回成功、获得固定 run ID 后接纳。Go 在同一 SQLite 事务中核对实际 `runs` / `threads_meta`：真实 owner、interactive origin、普通 run、当前 incarnation、无项目范围，原消息 ID/正文哈希与请求匹配。客户端 metadata 不能授予来源资格。
3. 原消息身份/哈希决定操作 ID；同消息重试复用原操作。原操作被遗忘后不会再次建立事实；新的明确消息有新的身份。
4. 来源引用与现有事实/投递账本原子提交。来源只保存 ID、哈希、版本及时间，不另存原对话正文。使用现有单并发持久存储队列，不重放聊天或 Native。
5. 采集前后校验个人策略与全局遗忘版本；用户手动纠正也推进该版本。迟到的自动保存失效，显式单事实投递仍只受目标屏障约束。
6. Python 在规范写入、检索排名和注入前检查来源 owner、原消息、run 与 incarnation。来源删除/变更后立即不参与召回；管理页展示“来源已不可用”并保留遗忘清理入口。手动纠正转为用户直接维护的事实。

每用户每天最多 50 条、实例每天最多 500 条明确采集（UTC 日），再受现有 2,000 条未清理事实/用户上限约束。原聊天不因采集关闭、超限、未知响应或存储失败而重发或失败；来源未获接纳时不声称保存。后台额外模型调用为零。

## 验收

- 默认关闭；开关有独立版本，旧 schema 升级保留资料、事实、账号及登录。
- 合格中英文指令保存并可打开来源；普通问题、助手/通知/回放、引用/附件、项目消息不采集。
- 实际上游接纳、规范消息与 owner/incarnation 不匹配时拒绝；不信任客户端来源标签。
- 同消息双击/重试只有一个事实；遗忘后旧消息不能复活，新明确消息可重新记住。
- 在接纳/提交之间关闭、纠正或遗忘，迟到保存失效；来源删除/改写后不检索或注入。
- 来源不可用仍可清理；手动纠正保留，且不会被来源删除一并撤下。
- 单用户与实例配额生效，失败不修改聊天响应、不启动模型/Native。
- Go race、固定 DeerMem/SQLite 契约、实际 Go→Gateway 采集、前端类型/生产构建及浏览器检查分别记录；不推断云部署或真实模型验收。
