# Agent 授权与连接

在账号管理页打开 **Agent 授权**，或访问 `/admin/agents`。本模块首期供单一设备 owner 使用；其他管理员不能借平台 MCP 使用这位 owner 的设备。普通账号仍不开放远程执行。

## 页面上能看到什么

每条记录展示设备、Codex、已登记项目、操作范围、授权截止时间和剩余时长；**授权状态、最近设备心跳、Worker 最近观测、原生 Agent 执行就绪分别显示**。可达观测超过 90 秒即过时。连接检查不运行 Codex，也不提交测试任务。

截止时间是用户选择的产品权限，不由部署脚本默认为 24 小时。支持 1 小时、24 小时、7 天、30 天、自定义 UTC 截止和直到手动撤销。页面按浏览器时区展示绝对时间及偏移；自定义输入明确使用 UTC，避免夏令时重复时间产生歧义。到期前 24 小时显示“即将到期”；首期不发送后台邮件或站外提醒。

## 连接本机

在受信的 Python 3.11+ 环境安装本版本 DeerMate。现有 Worker 需要升级并重启加载本版本的本地授权检查；保留原 state_dir、数据库、实例身份、项目配置与 Codex 登录。先核对没有正在执行的任务，不能通过删除状态目录来“重新连接”。

1. 在网页点击“连接设备”，生成 10 分钟有效的一次性配对命令。
2. 在设备运行该命令，使用实际 `worker.toml` 路径。本机 Worker 必须正在监听 `127.0.0.1:18777`。
3. 在设备运行 `deermate-device connect`，连接器主动通过既有 HTTPS 域名/IP 连接云端；无需开放本机端口或修改系统 sshd。
4. 回到页面添加授权，明确选择项目、操作范围、有效期和到期任务策略。
5. 页面提交后显示“待本机确认”。在本机另一个终端运行详情中的 `deermate-device approve --grant 授权ID`，核对服务器、设备、版本、项目、权限和期限，手动输入 `AUTHORIZE`。批准不会由模型消息、任务文本或网页内容替代。

连接器状态默认保存在 `~/.deermate-device`，权限仅当前用户可读。可用全局 `--state /绝对路径` 选择独立目录；配对、连接和批准都必须使用同一目录。首期连接器以前台进程运行，系统服务安装与开机启动另行配置；退出连接器后页面会显示过时/离线状态。

## 续期、取消和撤销

续期在本机确认前不改变原截止时间。可以取消待确认的申请；旧有效授权继续遵守原期限。错误或离线不会自动授权、补交任务或新建原生会话。已撤销的记录不能恢复为有效授权，需要重新申请。

到期立即禁止新增/续接任务，排队但未开始的任务不会启动。用户可选让已开始任务在原任务硬时限内完成，或请求停止。撤销默认禁止新任务并请求停止，本机确认撤销与原生任务确认停止是两个事实；停止结果继续查看原任务。已保存的云端历史和证据不会随到期删除。

本机还要求最近 90 秒内的授权观测，使用墙上时钟和单调时钟校验；时钟回拨、重启后的陈旧观测和断线不能使新任务继续获准。云端撤销立即拒绝新操作；设备分区时，已取出的请求存在至多剩余 90 秒观测窗口。已经开始且选择允许完成的任务仍受原硬时限约束。

## 维护边界

Codex 登录和 Worker 全权本地 token 留在本机。云端和连接器均执行项目、操作、设备实例及任务归属检查。云端持有逐授权、逐版本的 MCP 凭据；每次操作仍核对当前权限，版本变更会更换凭据。首期不承诺自动定期轮换设备身份凭据，不提供共享租户、任意原生命令、公开 Worker HTTP 或对云端管理员隐藏任务明文。

原临时 SSH 授权可以导入为已过期历史。导入不恢复密钥、隧道或可用 token；使用“重新连接设备”走新流程。旧 SSH 传输仍可按原操作员配置使用，本模块不延长它的期限。

实现与设计取舍见 [功能规格](specs/agent-authorization.md)和 [ADR 0014](decisions/0014-user-managed-agent-authorization.md)。
